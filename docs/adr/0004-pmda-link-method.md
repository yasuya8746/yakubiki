# ADR-0004: PMDA 添付文書ページへのリンク方式

- 日付: 2026-10-26
- ステータス: 承認済み(2026-10-28 人間が承認)
- 関連: `docs/requirements/drug-search-beta.md`, ADR-0001(第2版), ADR-0002(第2版)

## 背景
- ADR-0001 第2版により、アプリは添付文書本文を持たず、検索した薬剤の **PMDA 添付文書ページへのリンク**を表示する。
- PMDA の規約(人間が確認済み。https://www.pmda.go.jp/0048.html 、 https://www.pmda.go.jp/searchhelp_005.html ):
  - 自動で巡回してダウンロードするアプリケーションは一切認めない。
  - リンクは事前連絡不要で自由。リンク先が移動したら速やかに修正する義務がある。
- インデックスの元データ(厚労省 薬価基準収載品目リスト)が持つのは、品名・成分名・規格・メーカー名・薬価基準収載医薬品コード(12桁)など。PMDA の個別ページの URL や版番号は含まれない。
- **制約: リンク URL は「インデックスが持つ情報だけ」から作る必要がある。** URL を作るために PMDA のページを取得すること(例: 検索結果から個別ページの URL を拾う)は自動巡回にあたるため行わない。

### 本ADRの情報の確度(重要)
- WebFetch / WebSearch が使えず、**PMDA の URL 形式は本日時点で確認できていない**。以下の URL 形式は計画担当の一般知識に基づく「候補」であり、動作も安定性も未確認。
- 確認は T02(スパイク)で、**人がブラウザで代表品目を手作業で開いて行う**(スクリプトによる取得はしない)。

## 選択肢
| 案 | 概要 | 想定 URL の例(未確認) |
|---|---|---|
| L1 | 個別ページへ直接リンク: コード(YJコード/薬価基準コード)から、その品目の添付文書ページの URL を組み立てる | 旧来から知られる `https://www.info.pmda.go.jp/go/pack/<YJコード>_<版などの番号>/` 形式 など |
| L2 | 成分単位の一覧ページへリンク: 同じ成分の製品一覧ページを開き、利用者が製品を選ぶ | `https://www.pmda.go.jp/PmdaSearch/iyakuDetail/GeneralList/<コードの先頭7桁など>` 形式 など |
| L3 | PMDA 検索画面へ遷移し、検索語を渡す: URL のパラメータで品名を渡せればそれを使う。渡せなければ、品名をクリップボードにコピーして検索画面を開き「貼り付けて検索してください」と案内する | `https://www.pmda.go.jp/PmdaSearch/iyakuSearch/` |
| L4 | L1/L2 を主とし、L3 を常に併設するハイブリッド。どの方式を使うかは配信データ(ADR-0002 第2版の manifest)の URL テンプレートと品目ごとの上書き表で切り替える | – |

| 利用者の手間 | ◎ 1タップで原文 | ○ 一覧から製品を選ぶ | △ 検索操作が要る(パラメータ不可なら貼り付けも) | ◎〜○ |
| URL の安定性 | **△〜×(未確認)**。URL に版番号などが含まれる場合、改訂のたびに変わる。版番号はインデックスに無いので作れない | ○(未確認)。成分単位なので改訂の影響は受けにくい見込み | ◎ 検索画面のトップは最も変わりにくい | テンプレートを差し替えれば全品目を一度に直せる |
| 誤った薬に飛ぶ危険 | 中。コードの対応ずれ(後述)があると別製品が開く | 低〜中。一覧から選ぶ際に取り違える可能性(名称類似) | 低。利用者が検索結果を見て選ぶ | 方式に応じる |
| コードの対応 | 薬価基準コードと YJコードは多くの品目で一致すると認識しているが、**一般名で収載される品目などは一致しない**(要確認)。S1 だけでは正しい YJコードが分からない品目がある | 先頭の桁(成分・剤形の部分)だけを使うなら対応ずれの影響は小さい見込み | コード不要 | 品目ごとに方式を選べる |
| 規約 | リンクは自由(確認済み) | 同左 | 同左 | 同左 |
| 実装 | 小(テンプレートにコードを入れるだけ) | 小 | 小(コピー+ブラウザ起動) | 小〜中(テンプレートと上書き表の仕組み) |

### テンプレート形式の要約
| 案 | メリット | デメリット | リスク |
|---|---|---|---|
| L1 | 最短で原文に届く | 安定 URL が無ければ成り立たない | リンク切れ・別製品へのリンク |
| L2 | 改訂に強い見込み | 製品を選ぶ一手間 | 一覧での取り違え。PMDA 改修で URL が変わる |
| L3 | 最も壊れにくい。コード不要 | 手間が多い | 検索語の渡し方が変わると貼り付け案内に戻る |
| L4 | 壊れたときに全体を素早く直せる。品目ごとに最適な方式 | 仕組みが少し増える | 上書き表の運用を怠ると古いまま |

## 決定(提案)
1. **案L4(ハイブリッド)を採用する。** 詳細画面に次の2つのボタンを置く。
   - 主ボタン「PMDA で添付文書を見る」: T02 の確認結果で、**版番号を含まない安定した URL 形式が確認できれば L1、できなければ L2** を使う。
   - 副ボタン「PMDA の検索画面で探す」(L3): 常に表示する。品名をクリップボードにコピーし、検索画面を開く。検索語を URL で渡せることが確認できれば渡す。
   - 検索結果0件の画面にも L3 のボタンを出す(インデックスに無い薬を探せるように)。
2. **URL は配信データで切り替えられるようにする。**
   - manifest に URL テンプレート(L1/L2/L3 ごと)を持たせ、アプリはそれを使って URL を組み立てる。テンプレートの初期値はアプリにも同梱する。
   - 品目ごとの「リンク上書き表」(コード → 使う方式 / 固定 URL / リンク無効化)を配信データに持たせる。コードの対応ずれが分かった品目や、リンクが切れた品目を個別に直す。
   - これにより、PMDA 側の移動に**アプリの更新なしで、データの差し替え(手動起動で数分〜1時間程度)だけで対応する**。これを「速やかに修正する義務」への対応手段とする。
3. **リンクを開く前に取り違えを防ぐ。**
   - 詳細画面に、品名・成分名・規格・メーカー名・コードを表示し、ボタンの近くに「開いたページの販売名・規格がこの画面と一致するか確認してください」と表示する。
   - 対応ずれが疑われる品目(一般名で収載される品目など、T02 で特定)は、L1 を使わず L2/L3 にする。
4. **PMDA への自動アクセスをしない。**
   - リンクの死活確認を自動で行わない(サーバからの一括 HEAD/GET も、アプリからの事前チェックも行わない)。
   - アプリは外部ブラウザ(または Custom Tabs)で開くだけにする。**Custom Tabs の事前読み込み(`mayLaunchUrl` 等)は使わない**。WebView で PMDA のページを表示・解析・保存しない。
   - 開発者の調査も、手作業のブラウザ操作に限る(スクリプト・自動テストで PMDA にアクセスしない)。
5. **リンク切れ・誤リンクの検知は、自動チェックの代わりに次の3つで行う。**
   - 利用者からの報告: 詳細画面に「リンクが開けない/違う薬が表示された」報告ボタンを置く。押すとメールアプリが起動し、コードと品名が入った文面を作る(利用者が送信を選んだときだけ送られる。自動送信しない)。
   - 定期の手作業確認: データ更新時(月次程度)と月1回、QA または運用者が抽出した品目(例: 新規収載品+無作為20品目+L1 方式の代表品目)をブラウザで開いて確認する。手順は runbook に書く。
   - PMDA サイトのお知らせ(サイトの改修・URL 変更)を運用者が確認する。
   - 報告や確認でリンク切れが分かったら、目標「確認から1営業日以内」にテンプレートまたは上書き表を直して配信する(目標値は人間が決める)。

## 影響・結果
- T02 のスパイクに「PMDA の URL 形式の手作業確認」を加える。確認項目: 個別ページ URL に版番号が含まれるか、改訂後も同じ URL で開けるか、成分一覧ページの URL 形式、検索画面に検索語を URL で渡せるか、薬価基準コードと YJコードが一致しない品目の例。
- 配信データに URL テンプレートとリンク上書き表を含める(ADR-0002 第2版)。
- runbook(ops)に、リンク切れの報告受付・確認・修正・配信の手順と担当者を書く。
- 報告ボタンのメール送信先を決める必要がある(FR-7 のフィードバック先と共通にしてよい)。
- 人間が決める事項: リンク修正の目標時間、報告の受付担当者、L1 の安定 URL が確認できなかった場合に L2 を主ボタンにすることの了承。
- 将来、PMDA に「少数のリンクの自動死活確認」が許されるかを問い合わせる場合は、回答を記録して新ADRで扱う(β では行わない)。

## 追記(2026-10-28): L1 の URL 形式の確認結果

- PMDA 自身の資料に、YJコードから医療関係者向けの関連情報一覧を開くリダイレクトページの形式が示されていた: `https://www.pmda.go.jp/PmdaSearch/rdSearch/02/[YJコード]?user=1`
  - 版番号を含まず、PMDA が外部からのリンク用に案内している形式のため、L1 の第一候補とする。
  - 出典: https://www.pmda.go.jp/files/000240415.pdf
- 添付文書 PDF への直接リンク(`.../PmdaSearch/iyakuDetail/ResultDataSetPDF/[添付文書番号_版数]`)は添付文書番号と版数が必要で、インデックスに無いため使わない。
- 上記の動作(代表品目で正しい製品が開くか)は T02 で人がブラウザで確認する。確認できれば L1 = rdSearch 形式を主ボタンにする。

## 追記(2026-10-30): T02 の手作業確認(途中経過)

- 人がエミュレーターの Chrome で rdSearch 形式の URL を手作業で開き、**薬価基準収載医薬品コードと YJコードが一致する品目では、その製品のページが表示される**ことを確認した(スクリプト・自動ツールは使っていない)。
  - 確認済み: 1品目(内服薬・先発品: ロキソニン)。コード一致、正しい製品が表示された。
  - 表示されたのは「医療用医薬品情報(医療関係者向け)」のページで、販売名・一般名/成分名・製造販売業者と、添付文書・患者向医薬品ガイド・インタビューフォーム・RMP の各項目が並ぶ。
  - 販売名は「ロキソニン錠60mg／ロキソニン細粒10%」と、**同じ添付文書を共有する別剤形がまとめて1ページに表示**された。アプリの一致確認文は「販売名に検索した品目が含まれるか」を確かめる書き方にする(T11)。
  - rdSearch の URL は**別の URL へ転送**され、表示後のページの URL は `https://www.pmda.go.jp/PmdaSearch/rdDetail/iyaku/1149019C1149_1?user=1` だった。
    - 12桁のコード(`1149019C1149`)に `_1` が付く形。`_1` が版数か枝番かは未確認。転送先は PMDA 側で変わりうるため、アプリは転送先ではなく rdSearch 形式を保存・使用する。
    - 錠剤のコード `1149019F1560` で rdSearch を開いても、転送先 URL は細粒のコード `.../rdDetail/iyaku/1149019C1149_1?user=1` だった。**転送先は入力したコードではなく、添付文書ごとの代表コードになる**。転送先 URL のコードから、選んだ品目を判断してはいけない。
    - 剤形違いのコードでも、添付文書を共有する品目は同じページに集約される。
  - **一致しないコードの例**: 錠剤のもう一つのコード `1149019F1013` で `https://www.pmda.go.jp/PmdaSearch/rdSearch/02/1149019F1013?user=1` を開くと、「品目選択」画面に「**該当する品目はありませんでした。**」と表示された。
    - 上位7桁(`1149019`)と剤形(`F`)が同じでも、末尾が違うと rdSearch では開けない。
    - 2つとも厚労省リストに載っている薬価基準収載医薬品コード。`F1560` は「ロキソニン錠６０ｍｇ」(第一三共、先発品)、`F1013` は「ロキソプロフェンナトリウム６０ｍｇ錠」(メーカー空欄の一般名収載品)。**一般名収載品のコードは rdSearch で開けない**(ADR-0001 追記 2026-10-30)。
    - **影響**: インデックスに入れるコードが rdSearch の受け付けるコード(YJコードとみられる)と一致しない品目では、L1 が「該当なし」になる。一致しない品目を厚労省リストの調査で特定し、L2/L3 に回すか、YJコードの入手方法を検討する(ADR-0001 の S3)。
    - 「該当なし」は通常のページとして表示されるため、利用者からの報告以外で検知できない。
- 後発品: `1149019C1157`(ロキソプロフェンＮａ細粒１０％「サワイ」、リストのメーカーはメディサ新薬)で rdSearch を開くと、「ロキソプロフェンNa錠60mg「サワイ」／ロキソプロフェンNa細粒10%「サワイ」」のページが表示された(製造販売元 メディサ新薬、発売元 沢井製薬)。後発品でも、メーカー名のある品目はリストのコードで開け、剤形違いが1ページに集約される。
  - リストの品名は全角(`Ｎａ`、`１０％`)、PMDA の表示は半角(`Na`、`10%`)。アプリで品名を表示するときは、PMDA の表示と見比べやすいよう英数字を半角にそろえる(T05 の正規化で扱う)。
- 注射薬(後発品): `2219402A1049`(ナロキソン塩酸塩静注０．２ｍｇ「ＡＦＰ」)で rdSearch を開くと、「ナロキソン塩酸塩静注0.2mg「AFP」」(製造販売元 アルフレッサ ファーマ)の単独のページが表示された。注射薬もリストのコードで開ける。
- 外用薬(メーカー空欄): `2649735R1018`(ロキソプロフェンナトリウム１％噴霧液)で rdSearch を開くと「該当する品目はありませんでした。」だった。内用薬の `1149019F1013` と同じく、**メーカー空欄の一般名収載品は区分を問わず rdSearch で開けない**(2件で確認)。
- 局方品(メーカー空欄): `1112700X1011`(ハロタン)で rdSearch を開くと「該当する品目はありませんでした。」だった。一般名収載品だけでなく、**メーカー空欄の局方品も rdSearch で開けない**。リストの「メーカー名が空欄」を、L1 を使わない条件にできる(3件で確認)。
- 外用薬(先発品): `2649735Q1020`(ロキソニンゲル１％)で rdSearch を開くと、「ロキソニンゲル1%」(製造販売元 第一三共)のページが表示された。
- **ここまでのまとめ(7件)**: メーカー名のある品目は内用・注射・外用、先発・後発を問わず、リストのコードで rdSearch が開けた(4件)。メーカー空欄の品目は一般名収載品・局方品とも開けなかった(3件)。リストの「メーカー名」の有無で L1 を使うかを振り分ける。
- 検索画面(L3): 「医療用医薬品 情報検索」で一般名・販売名に「ロキソプロフェン」を入れて検索すると 62件(7ページ)が表示されたが、結果画面の URL は `https://www.pmda.go.jp/PmdaSearch/iyakuSearch` だけで、**検索語は URL に含まれない**(フォーム送信)。アプリから検索語を渡して結果を直接開くことはできない。L3 は検索画面を開き、利用者に成分名を貼り付けてもらう案内になる。結果画面はスマートフォン向けの表示ではない。
- 成分一覧(L2): 検索結果の一般名リンク「ロキソプロフェンナトリウム水和物」を開くと、URL は `https://www.pmda.go.jp/PmdaSearch/iyakuDetail/GeneralList/1149019` だった。
  - **末尾はリストのコードの上7桁**(`1149019`)。同じ成分・同じ投与経路の製品(先発・後発)が、販売名・製造販売業者・添付文書(PDF/HTML)の表で並ぶ。
  - リストのコードから URL を組み立てられるため、**メーカー空欄の品目の主ボタンを L2(`GeneralList/[コード上7桁]`)にできる見込み**。
  - この URL を直接入力しても、同じ一覧が開けた(人が確認)。
  - 外用薬 `GeneralList/2649735` も直接入力で開け、ロキソニンゲル・テープ・パップと後発品のゲル・テープなどが一覧で表示された。ゲル・テープ・パップなど剤形の違う外用薬が1つの一覧に入る。
  - 局方品 `GeneralList/1112700`(ハロタン)は、ページ自体は開き一般名「ハロタン」が表示されたが、**販売名・添付文書の行が1つも無い空の一覧**だった。エラーにはならないため、空かどうかは開くまで分からない。
    - 販売中の製品が無い成分などでは、L2 も役に立たない。どの成分が空かを事前に調べるには PMDA へのアクセスが必要で、自動では確認しない。
    - 対策: L2 を主ボタンにする品目では、副ボタン「PMDA で検索する」(L3、成分名のコピー付き)を必ず並べ、「一覧が空のときは検索してください」と添える。
- 確認できなかった・残した項目:
  - 代表品目は目標20品目に対し、rdSearch 7品目・成分一覧 3成分・検索画面 1件の確認にとどめた。区分(内用・注射・外用)、先発・後発、一般名収載品、局方品は網羅した。件数の不足は QA の抜き取り検証(T11 以降)で補う。
  - 転送先 URL の `_1` が版数か(アプリは rdSearch 形式を使うため判断に影響しない)。
- **決定(D12、2026-10-30 人間が承認)**: 次の推奨を採用する。確認件数が目標20品目に満たない点も、現状で可とする。
  - メーカー名のある品目(約87%): 主ボタン = L1 `https://www.pmda.go.jp/PmdaSearch/rdSearch/02/[コード12桁]?user=1`
  - メーカー名が空欄の品目(約13%): 主ボタン = L2 `https://www.pmda.go.jp/PmdaSearch/iyakuDetail/GeneralList/[コード上7桁]`
  - すべての品目: 副ボタン = L3(PMDA の検索画面を開く。検索語は URL で渡せないため、成分名・品名のコピーボタンを付ける)
  - 開いたページの販売名に選んだ品目が含まれるかを確かめる文言を出す(剤形違いが1ページに集約されるため)。

## 追記(2026-10-30): 表示名の半角化の範囲
- 上の「英数字を半角にそろえる」は、ADR-0005 5.1 で「全角英数字・記号(U+FF01〜U+FF5E)だけを半角にする」と範囲を決めた。NFKC 全体は公式の表記(㎎、Ⅱ など)まで変えるため、表示には使わない。
