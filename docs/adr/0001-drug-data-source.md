# ADR-0001: 薬剤データの取得元

- 日付: 2026-10-26(第1版)/ 2026-10-26(第2版 追記)
- ステータス: 承認済み(2026-10-28 人間が承認)
- 関連: `docs/requirements/drug-search-beta.md`, ADR-0002, ADR-0003, ADR-0004

> **第2版で決定を変更した。** PMDA の規約確認の結果、第1版の推奨(案A: PMDA から本文を自動取得してアプリに保存)は不可となり、ユーザーが「リンク方式」(第1版の案D 相当)に決めた。
> 現行の提案は末尾の「第2版(2026-10-26 追記): リンク方式への変更と検索インデックスのデータ源」を参照。第1版の本文は経緯として残し、書き換えない。

## 背景
- β版アプリは、医療用医薬品について 名前・用途(効能・効果)・成分・副作用・併用禁忌 を表示し、1日1回データを更新する必要がある。
- 医療情報なので「公式性・最新性」が重要。また、アプリ内に保存して配布する=第三者への**再配布**にあたる可能性があるため、利用規約・著作権の確認が必須。
- 併用禁忌は「相手薬剤名」「臨床症状・措置方法」「機序・危険因子」の組で表示したく、構造化されているかで実装工数が大きく変わる。

### 注意(本ADRの情報の確度)
- 以下の規約・提供形態に関する記述は、計画担当の一般知識に基づく整理であり、**本日時点の各サイトの規約原文は未確認**。「要確認」と書いた項目は、人間が原文を確認するか、提供元に問い合わせる必要がある。
- 規約が明確に許可していない利用は「グレー」として扱い、許可が取れるまで本番データとして配布しない。

## 決定(提案)
- **一次ソース: 案A(PMDA 添付文書情報)** を推奨。ただし「利用条件の確認(下記の人間確認事項)」をW1中に完了することを着手条件とする。
- **名称・コード・規格の補助: 案D のマスタ**(薬価基準収載品目リスト または HOTコードマスタ)を併用し、検索用の名称正規化・品目同定に使う。
- **縮退案(Plan B)**: 規約確認でAの本文保存・再配布が不可/回答待ちの場合、β版は **案D(リンク型)** で出し、詳細画面は「マスタ情報+原本リンク」とする。オフラインで本文が読めない旨を要件の例外として人間が承認する。
- **将来案**: 一般公開や併用チェック機能に進む場合は、案B または 案C のライセンス取得を再検討する(新ADRで置き換え)。
- 取得は ADR-0002 のサーバ側バッチで行い、取得元へのアクセスは「1日1回・差分中心・低頻度(例: 1リクエスト/数秒)・User-Agent に連絡先を明記」とする。

## 人間が確認すべき点(規約・ライセンス)
1. **PMDA サイトの利用規約・サイトポリシー**: 掲載情報の複製・転載・二次利用の条件、出典表示の方法、機械的な自動取得(クローリング)の可否と制限。
2. **添付文書本文の著作権**: 製造販売業者の著作物として扱われるか。原文のままアプリ内に保存・表示することに許諾が要るか。必要なら PMDA または業界団体(日本製薬団体連合会 等)への問い合わせ先。
3. **PMDA の公式な一括取得手段の有無**: データ提供サービス、一括ダウンロード、API 等があれば、スクレイピングより優先する(規約・負荷の両面で有利)。
4. **KEGG のライセンス**: 本アプリ(組織内の関係者限定・無償配布)が学術利用の範囲に入るか、商用ライセンスが必要か。費用と契約期間。
5. **商用DB(JAPIC 等)**: β期間限定・少人数での試用契約が可能か、見積もり、端末保存を含む再配布の可否。
6. **公的マスタ**(薬価基準収載品目リスト / HOTコードマスタ)の利用条件と出典表示の要否。
7. 運営主体(組織名)と利用目的(非営利/営利)。規約判断の前提になる。

## 影響・結果
- W1 に「規約確認(人間)」と「PMDAデータのスパイク(構造・件数・サイズ・併用禁忌表の取得可否)」を置く。スパイク結果でデータ量の見積もり(ADR-0002)を確定する。
- データモデルは取得元に依存しない形(品目・成分・セクション・相互作用)で設計し、Plan B / 将来の B・C 案へ差し替え可能にする。
- 詳細画面には出典・原本リンク・改訂年月・取得日時を必ず表示する(要件 FR-2)。
- 解析に失敗した項目は推測で埋めず「情報なし。原本を確認してください」と表示する。

## 第2版(2026-10-26 追記): リンク方式への変更と検索インデックスのデータ源

### 経緯(第1版からの変更理由)
- PMDA の規約を確認した(人間が確認。確認元: https://www.pmda.go.jp/0048.html 、 https://www.pmda.go.jp/searchhelp_005.html )。
  - 自動で巡回してダウンロードするアプリケーションによるアクセスは「一切認めておりません」とあり、**全面禁止**。
  - 添付文書の著作権は製造販売業者にあり、無断での複製・転載・頒布は禁止。
  - リンクは事前連絡不要で自由。ただし**リンク先が移動したら速やかに修正する義務**がある。
- このため第1版の案A(PMDA から本文を取得してアプリに保存)は、取得(自動巡回の禁止)と保存・配布(著作権)の両面で不可。案B・案C(KEGG・商用DB)はβの期間と費用に合わないため、第1版と同じく将来案にとどめる。
- ユーザーが方針を決定: **アプリで薬剤名を検索し、該当薬剤の PMDA 添付文書ページへのリンクを表示する。用途・成分・副作用・併用禁忌の本文はアプリに保持しない。**

### 第2版の論点
アプリが持つのは「検索インデックス」(品名・一般名/成分名・規格・製造販売業者・コード)だけになる。本ADR第2版では、このインデックスのデータ源を決める。リンクの作り方は ADR-0004、データの配り方は ADR-0002 第2版で扱う。

### 本節の情報の確度(重要)
- 計画担当の作業環境では **WebFetch / WebSearch が使えず、各サイトの原文を本日時点で確認できていない**。以下の「利用条件」「更新頻度」「収録項目」は計画担当の一般知識に基づく整理であり、確認済みの事実ではない。
- 確認済みの事実は、上記「経緯」にある PMDA の規約(人間が確認したもの)だけである。
- 表中の「要確認」は、T01(規約確認)で人間が原文を確認する。

### 決定(提案・第2版)
1. **β版のインデックスは S1(厚労省 薬価基準収載品目リスト)を単独で使う**ことを推奨する。
   - 理由: 一覧表示に必要な項目がそろい、利用条件が「出典表示で再配布可」の政府系規約である見込みが高く、実装が最小。
   - 出典表示: アプリの設定画面とリリースノートに「出典: 厚生労働省『薬価基準収載品目リスト』(○年○月○日版)を加工して作成」と表示する(規約が求める形式に合わせる)。「加工」の内容(列の取捨・名称の正規化)も明記する。
   - 薬価の列は取り込まない(要件のスコープ外。表示しない)。
2. **S2(カナ名称)と S3(YJコード)は β では入れず、T01 の規約確認と T02 のスパイク結果で追加を判断する**。
   - S3 は ADR-0004 で「薬価基準コードから PMDA へ直接リンクできない品目」が多いと分かった場合に優先度を上げる。
   - S2 は「漢字を含む名称をひらがなで探せない」ことが β テストで問題になった場合に追加する。
3. **取得頻度**: サーバ側で **1日1回、厚労省の公開ページを1回だけ取得して更新の有無を確認し、更新があったときだけ該当 Excel(数ファイル)を取得する**(詳細は ADR-0002 第2版)。
   - 規約上の評価(仮): 1日1ページ+更新時に数ファイルという量は、人がブラウザで確認する頻度と変わらず、PMDA が禁じるような「自動巡回」とは性質が異なる。政府標準利用規約/PDL には、計画担当の知る範囲で自動取得の禁止条項は無い。**ただし原文未確認のため、T01 で人間が「厚労省サイトの利用規約・リンク/著作権ページに自動取得の制限が無いこと」を確認するまでは、スケジュール実行を有効にせず、手動起動で運用する。**
   - アクセス時は User-Agent に連絡先を明記し、条件付き取得(If-Modified-Since / ETag)が使えれば使う。
4. **PMDA へは、サーバからもアプリからも自動でアクセスしない**。リンクの検証も自動では行わない(ADR-0004)。
5. **第1版の推奨(案A を一次ソースとする)は撤回する**。第1版の「将来案」(KEGG・商用DBのライセンス取得による本文表示)は、一般公開や併用チェックを検討する時点で新ADRとして再検討する。
