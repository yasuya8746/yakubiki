# ロードマップとタスク分解(薬剤検索アプリ β版、約4週)

- 作成日: 2026-10-26(第1版)/ 改訂: 2026-10-26(第2版: リンク方式)
- ステータス: 承認済み(第2版、2026-10-28 人間が承認)
- 関連: `docs/requirements/drug-search-beta.md`, `docs/requirements/drug-search-beta-risks.md`, ADR-0001〜0004
- 前提: 実働は developer 1名相当+ qa / release-manager / ops の並行作業。ADR は推奨案(ADR-0001 第2版 S1、ADR-0002 第2版 E3→E2、ADR-0004 L4)で承認される想定。

## 0. 第2版での変更点
- **削除したタスク**(本文を持たないため不要): PMDA データ取得スパイク(本文構造・併用禁忌表の調査)、PMDA 差分取得、本文の解析・正規化(セクション・併用禁忌表)、本文のデータ抜き取り検証(原本との突き合わせ)。
- **縮小したタスク**: 変換ジョブ(第1版の取得 1.5+解析 2+品質ゲート 1.5 = 5日 → 2.5日)、Room スキーマ(相互作用・セクション表が無くなる)、詳細画面(本文表示 → 品目情報+リンク)。
- **追加したタスク**: PMDA URL 形式の手作業確認(スパイクに統合)、同梱データ、リンク上書き表・URL テンプレート、報告ボタン、リンク抜き取り検証、リンク修正の runbook。
- **工数**: developer 21 → **14人日**(バッファ2日を含む)。全体 約27 → **約21人日**。
- タスクIDは振り直した(まだ Issue 化していないため)。旧IDとの対応は 5章。

### スケジュール超過時の削減候補(優先度の低い順に削る)
1. 手動「今すぐ更新」(FR-3.5)
2. 未同期の警告表示(日時表示自体は残す)
3. 報告ボタンのメール下書きへの自動差し込み(送付先の表示だけ残す)
4. Firebase App Distribution の補助導入

※ URL テンプレート・リンク上書き表の配信(FR-8.1)は PMDA 規約の修正義務に関わるため、削減しない。

## 3. 各タスクの受け入れ条件(Issue 本文用)

### T01 厚労省リストの利用条件・自動取得の可否の確認
- [ ] ADR-0001 第2版「人間が確認すべき点」1〜5 の回答を、確認した URL・日付とともに記録した
- [ ] 出典表示と「加工した旨」の文言を決めた
- [ ] 変換ジョブを日次自動(E2)にしてよいか、手動起動(E3)のままにするかを決めた
- [ ] 結果を ADR に追記した(決定が変わる場合は置き換え ADR を作成)

### T02 スパイク: 厚労省リストの構造調査+PMDA URL 形式の手作業確認
- [ ] 厚労省リストの公開ページ URL、ファイルの分け方、列構成、品目数、変換後・圧縮後のサイズを記録した
- [ ] YJコードが含まれるかを確認し、無ければ薬価基準コードと YJコードが一致しない品目の種類(一般名収載品など)と件数の見込みを記録した
- [ ] **人がブラウザで**代表20品目(先発・後発・一般名収載品・注射薬・外用薬を含む)の PMDA ページを開き、個別ページ URL に版番号などが含まれるか、成分一覧ページの URL 形式、検索画面に検索語を URL で渡せるかを記録した
- [ ] 確認にスクリプト・自動ツールを使っていない(PMDA へのアクセスは手作業のみ)
- [ ] 結果から L1/L2 のどちらを主ボタンにするかの推奨を ADR-0004 に追記する材料を残した

### T03 プロジェクト基盤
- [ ] `gradle/libs.versions.toml` で依存を一元管理し、Kotlin DSL でビルドできる
- [ ] Compose・Hilt・Room・Retrofit・WorkManager が導入され、空画面が起動する
- [ ] パッケージ名を `com.example.myapp` から決定済みの名前へ変更した
- [ ] cleartext 通信を禁止する設定がある

### T04 CI 整備
- [ ] PR で ビルド・単体テスト・Lint が自動実行される
- [ ] 鍵・google-services.json・keystore.properties が .gitignore 済みで、混入時に CI が失敗する(または検出される)
- [ ] `batch/` とテストコードに PMDA ドメインへアクセスするコードがあれば検出される(アプリの URL テンプレート定義など、許可する箇所は明示的に除外)

### T05 データモデル・配信フォーマット設計
- [ ] 品目表(コード・品名・成分名・規格・区分・先発/後発・メーカー・正規化済み検索名・リンク方式)のスキーマを定義した。薬価・本文の列は持たない
- [ ] manifest(データ版ID・元データの公表日/適用日・生成日時・最終確認日時・件数・ハッシュ・スキーマ版・URL テンプレート)の仕様を定義した
- [ ] リンク上書き表(コード → 方式 / 固定URL / 無効化)の仕様を定義した
- [ ] reviewer が、将来の別データ源(読みデータ・YJコード)を列追加で足せる構造であることを確認した

### T06 変換ジョブ: 更新確認・取得・変換・正規化
- [ ] `workflow_dispatch` で起動でき、厚労省ページを1回取得して、掲載ファイルが前回と同じなら取得せず終了する
- [ ] 変わっていれば Excel を取得し、品目表に変換する(かな・全半角正規化、薬価列は捨てる)
- [ ] User-Agent に連絡先を設定し、再試行の上限がある
- [ ] 代表品目のスナップショットテストがある
- [ ] スケジュール実行の設定は用意するが、T01 の結論が出るまで無効にしておく

### T07 変換ジョブ: 品質ゲート・静的配信・通知
- [ ] 品目数の前回比減少(しきい値超過)・必須列の欠落のとき公開しない
- [ ] 公開時に manifest・インデックス(圧縮 SQLite)・リンク上書き表を配置する
- [ ] Excel を取得せずに、URL テンプレートとリンク上書き表だけを更新・配信できる
- [ ] 失敗・ゲート不合格時に運用者へ通知される
- [ ] デプロイ用の認証情報は CI シークレットのみで扱う

### T08 アプリ: Room+FTS+同梱データ
- [ ] 同梱データにより、初回起動直後から機内モードで検索できる
- [ ] 2万品目相当で部分一致検索が300ms以内(計測端末を記録)
- [ ] ひらがな/カタカナ・全半角の違いを吸収する
- [ ] Repository 経由で UI に Flow を提供し、単体テストがある

### T09 アプリ: 同期 Worker
- [ ] 24時間周期・ネットワーク接続時の条件で登録される
- [ ] manifest が新しい場合のみダウンロードし、ハッシュ検証後に切替える
- [ ] URL テンプレート・上書き表だけの更新も反映される
- [ ] 失敗時は指数バックオフで再試行し、旧データで利用し続けられる

### T10 検索画面
- [ ] 入力に応じて結果が更新され、品名・成分名・規格・製造販売業者を表示する
- [ ] 0件時に「該当なし」、データ版、「PMDA の検索画面で探す」、インデックスに無い場合がある旨、漢字でも検索するよう促す文を表示する
- [ ] フォント200%・TalkBack で操作できる

### T11 品目情報画面と PMDA リンク
- [ ] 品名・成分名・規格・製造販売業者・区分・薬価基準コードを表示し、本文・薬価は表示しない
- [ ] 主ボタンが URL テンプレート(と上書き表)に従って PMDA ページを外部ブラウザ/Custom Tabs で開く。事前読み込みをしない
- [ ] 副ボタンが品名をコピーして検索画面を開き、コピーしたことを表示する
- [ ] 上書き表で無効化された品目は副ボタンのみ表示する
- [ ] 一致確認の注意文、短い免責文、出典を表示する
- [ ] オフライン時はブラウザを開かず、通信が必要な旨を表示する
- [ ] 報告ボタンでメールの下書き(品名・コード・アプリ版・データ版)が作られる。自動送信しない
- [ ] UI テストではブラウザ起動をモックし、PMDA に実アクセスしない

### T12 免責同意・設定画面

- [ ] 設定画面に 免責全文・アプリ版・データ版・最終確認日時・最終同期日時・出典と利用条件・PMDA へのリンクである旨・OSSライセンス・フィードバック先 を表示する
